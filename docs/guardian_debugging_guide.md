# Guardian 浏览器自动化调试指南

## 常见问题及解决方案

### 1. "Failed to process prompt via browser automation" 错误

#### 可能原因：
- 目标AI服务需要登录才能使用
- DOM选择器不匹配（AI服务UI已更新）
- 安全策略阻止自动化访问
- 网络连接问题

#### 解决方案：
1. **确认AI服务可访问性**：
   - 手动在浏览器中访问目标URL，确保可以正常访问
   - 确认是否需要登录账号

2. **检查选择器配置**：
   - 使用浏览器开发者工具（F12）检查实际的DOM元素选择器
   - 更新GuardianClient中的选择器配置

3. **网络连接测试**：
   - 确保Docker容器可以访问外部网络
   - 检查防火墙设置

### 2. 选择器不匹配问题

#### 诊断步骤：
1. 启用非静默模式（headless=false）观察浏览器操作
2. 使用浏览器开发者工具检查正确的选择器
3. 更新GuardianClient中的选择器配置

#### 常见选择器模式：
- **DeepSeek**: `#prompt-textarea`, `button[type='submit']`, `.font-light`
- **ChatGPT**: `textarea[placeholder*='Send a message']`, `button[data-testid='send-button']`
- **Claude**: `[contenteditable='true']`, `button[data-testid='send-button']`

### 3. 登录要求问题

某些AI服务（如ChatGPT、Claude）需要登录才能使用。解决方案：

1. **配置用户数据目录**：
   - 在Chrome启动参数中添加 `--user-data-dir` 指向已登录的用户配置
   - 这样浏览器会保持登录状态

2. **使用已登录的浏览器实例**：
   - 手动登录AI服务
   - 确保浏览器会话保持活跃

## 调试技巧

### 1. 启用详细日志
在环境变量中设置：
```bash
LOG_LEVEL=debug
```

### 2. 非静默模式测试
在GuardianClient中设置：
```go
chromedp.Flag("headless", false)  // 便于观察浏览器操作
```

### 3. 逐步调试
使用以下步骤逐步验证浏览器自动化流程：
1. 验证URL访问
2. 验证元素定位
3. 验证内容输入
4. 验证提交操作
5. 验证响应获取

## 配置建议

### 1. 选择器配置最佳实践
- 使用更通用的选择器，如 `[role='textbox']` 而不是特定ID
- 提供多个备选选择器以提高兼容性
- 定期更新选择器以适应UI变更

### 2. 超时设置
- 增加页面加载超时时间
- 为AI响应生成预留足够时间
- 设置合理的整体超时限制

### 3. 错误处理
- 实现重试机制
- 提供清晰的错误信息
- 记录详细的调试日志

## 安全注意事项

1. **反自动化检测**：
   - 隐藏webdriver属性
   - 设置真实用户代理
   - 模拟人类操作行为

2. **合规使用**：
   - 遵守AI服务的使用条款
   - 控制请求频率避免滥用
   - 尊重服务的反爬虫机制

## 性能优化

1. **减少数据传输**：
   - 压缩提示词内容
   - 过滤不必要的数据
   - 优化上下文长度

2. **并发控制**：
   - 限制并发浏览器实例数量
   - 合理安排任务调度
   - 管理资源使用

## 故障排除清单

当遇到问题时，请按以下步骤检查：

- [ ] 目标AI服务URL是否正确
- [ ] 是否需要登录才能使用服务
- [ ] DOM选择器是否与当前UI匹配
- [ ] 网络连接是否正常
- [ ] 浏览器是否正确启动
- [ ] 是否有安全策略阻止访问
- [ ] 日志中是否有详细错误信息
- [ ] 上下文长度是否超过限制
