================================================================================
NOFX策略配置AI提示词文档使用说明
================================================================================

文档名称: strategy_config_ai_prompt.json
文档版本: 2.0
最后更新: 2026-02-23
文档用途: 指导AI生成符合NOFX系统要求的交易策略JSON配置

================================================================================
一、文档结构概览
================================================================================

本文档采用JSON格式，包含以下主要部分：

1. _document          - 文档元信息
2. _quick_start       - 快速上手指南
3. _schema_overview   - 整体结构说明
4. config             - 配置详细规范（核心部分）
5. _strategy_templates - 策略模板库
6. _validation_checklist - 验证检查清单
7. _complete_example   - 完整示例

================================================================================
二、各部分详细说明
================================================================================

--------------------------------------------------------------------------------
2.1 _document - 文档元信息
--------------------------------------------------------------------------------

作用：标识文档的基本信息
内容：
  - title: 文档标题
  - version: 版本号
  - last_updated: 最后更新日期
  - purpose: 文档用途说明
  - audience: 目标读者（AI助手/大语言模型）

使用建议：AI在生成配置前应先阅读此部分了解文档定位

--------------------------------------------------------------------------------
2.2 _quick_start - 快速上手指南
--------------------------------------------------------------------------------

作用：帮助AI快速理解如何生成策略配置

三个步骤：
  步骤1: 理解用户需求
         - 交易风格（保守/激进）
         - 目标币种
         - 风险偏好
  
  步骤2: 填写核心字段
         - name, description
         - config.language
         - config.coin_source
  
  步骤3: 根据交易风格调整参数
         - risk_control参数
         - indicators开关

minimal_example: 提供了一个最简化的配置示例，展示最基本的必填字段

--------------------------------------------------------------------------------
2.3 _schema_overview - 整体结构说明
--------------------------------------------------------------------------------

作用：说明JSON配置的顶层结构

root_fields: 根级别字段说明
  - name: 策略名称（必填，2-50字符）
  - description: 策略描述（必填，10-500字符）
  - config: 配置对象（必填）

export_metadata: 导出时自动添加的元数据
  - exported_at: 导出时间戳
  - version: 配置格式版本

--------------------------------------------------------------------------------
2.4 config - 配置详细规范（核心部分）
--------------------------------------------------------------------------------

这是文档的核心，包含策略的所有配置项：

----------------------------------------
2.4.1 language - 语言设置
----------------------------------------
  类型: string
  可选值: "zh" | "en"
  默认值: "zh"
  影响: 决定系统提示词和界面语言

----------------------------------------
2.4.2 coin_source - 币种来源配置
----------------------------------------

决定AI分析哪些币种的数据。

source_type - 币种选择模式（关键字段）：
  - "static": 固定币种列表
    * 适用场景: 只交易特定币种
    * 必填字段: static_coins
    * 示例: ["BTCUSDT", "ETHUSDT"]
  
  - "ai500": AI500热门币池
    * 适用场景: 追踪市场热门币种
    * 必填字段: use_ai500, ai500_limit
    * 示例: use_ai500: true, ai500_limit: 10
  
  - "oi_top": 持仓量Top币种
    * 适用场景: 追踪资金关注度高的币种
    * 必填字段: use_oi_top, oi_top_limit
    * 示例: use_oi_top: true, oi_top_limit: 10
  
  - "mixed": 组合模式
    * 适用场景: 同时使用多种来源
    * 可同时启用ai500和oi_top

其他字段：
  - static_coins: 静态币种列表（source_type='static'时必填）
  - excluded_coins: 排除币种列表（可选）
  - use_ai500/ai500_limit: AI500配置
  - use_oi_top/oi_top_limit: OI Top配置

----------------------------------------
2.4.3 indicators - 技术指标配置
----------------------------------------

决定AI分析时使用哪些数据和技术指标。

klines - K线数据配置：
  - primary_timeframe: 主时间周期
    * 可选值: "1m", "3m", "5m", "15m", "30m", "1h", "2h", "4h", "1d", "1w"
    * 推荐: 短线用"5m"/"15m", 中线用"1h"/"4h", 长线用"4h"/"1d"
  
  - primary_count: K线数量（默认30，范围10-500）
  - longer_timeframe: 更长周期（用于趋势判断）
  - enable_multi_timeframe: 是否多周期分析
  - selected_timeframes: 多周期列表
  - timeframe_counts: 各周期K线数量配置
  - trading_style_preset: 交易风格预设
    * "short": 短线（持仓分钟-小时）
    * "medium": 中线（持仓小时-日）
    * "long": 长线（持仓日-周）

technical_indicators - 技术指标开关：
  按策略类型推荐：
  - 趋势跟踪: enable_ema, enable_macd, enable_boll
  - 动量策略: enable_rsi, enable_macd
  - 波动率策略: enable_atr, enable_boll
  
  各指标说明：
  - enable_raw_klines: 原始OHLCV数据（必须启用）
  - enable_ema: 指数移动平均线（周期[20,50]）
  - enable_macd: MACD指标
  - enable_rsi: 相对强弱指标（周期[7,14]）
  - enable_atr: 平均真实波幅（周期[14]）
  - enable_boll: 布林带（周期[20]）
  - enable_volume: 成交量数据
  - enable_oi: 持仓量数据
  - enable_funding_rate: 资金费率数据

quantitative_data - 量化数据源：
  - nofxos_api_key: API密钥（有默认值）
  - enable_quant_data: 总开关
  - enable_quant_oi: OI数据
  - enable_quant_netflow: 资金流向数据
  - ranking_data: 排行数据（OI/资金流向/价格）

external_data_sources - 外部数据源（可选）：
  用于接入自定义API数据
  字段: name, type, url, method, headers, data_path, refresh_secs

----------------------------------------
2.4.4 risk_control - 风险控制配置
----------------------------------------

分为两类：代码强制执行 vs AI指导

code_enforced（系统强制执行）：
  - max_positions: 最大持仓币种数（1-10，默认3）
  - btc_eth_max_position_value_ratio: BTC/ETH仓位/净值比（1.0-10.0，默认5.0）
  - altcoin_max_position_value_ratio: 山寨币仓位/净值比（0.5-5.0，默认1.0）
  - max_margin_usage: 最大保证金使用率（0.1-0.95，默认0.9）
  - min_position_size: 最小仓位规模USDT（12-10000，默认12）
  - max_daily_trades: 每日最大交易次数（1-100，默认10）
  - max_hourly_trades: 每小时最大交易次数（1-20，默认3）
  - max_trades_per_symbol_per_hour: 每小时每币种最大次数（1-10，默认1）
  - min_hold_time_minutes: 最小持仓时间分钟（1-1440，默认8）
  - max_loss_per_trade_percent: 单笔最大亏损百分比（0.1-10.0，默认3.0）
  - daily_loss_limit_percent: 每日总亏损限制百分比（0.1-10.0，默认2.0）

ai_guided（AI参考决策）：
  - btc_eth_max_leverage: BTC/ETH杠杆（1-125，默认5）
  - altcoin_max_leverage: 山寨币杠杆（1-100，默认5）
  - min_risk_reward_ratio: 最小盈亏比（1.0-10.0，默认3.0）
  - min_confidence: 最小信心度%（50-100，默认75）

杠杆推荐值：
  保守: BTC/ETH 3-5x, 山寨币 3-5x
  平衡: BTC/ETH 5-10x, 山寨币 5-8x
  激进: BTC/ETH 10-20x, 山寨币 8-15x

----------------------------------------
2.4.5 custom_prompt - 自定义提示词
----------------------------------------

类型: string（可选，最大2000字符）
作用: 追加到系统提示词末尾
使用场景:
  - 添加特定交易规则
  - 强调某种分析方法
  - 指定特定市场条件处理方式

示例内容:
"特别关注美联储利率决议前后的市场波动，在重要数据发布前2小时减少仓位或暂停新开仓。"

----------------------------------------
2.4.6 prompt_sections - 可编辑提示词段落
----------------------------------------

类型: object（可选）
作用: 自定义系统提示词的各个段落

包含四个段落：
  - role_definition: AI角色定义
  - trading_frequency: 交易频率意识
  - entry_standards: 入场标准
  - decision_process: 决策流程

每个段落支持Markdown格式，留空则使用系统默认值。

--------------------------------------------------------------------------------
2.5 _strategy_templates - 策略模板库
--------------------------------------------------------------------------------

提供三个完整的策略模板供参考：

conservative_btc_eth - BTCETH保守策略：
  - 特点: 专注BTC/ETH，低杠杆(3x)，严格止损(2%)，长持仓(>60分钟)
  - 适用: 稳健型投资者
  - 配置亮点: max_positions=2, max_margin_usage=0.7, min_position_size=100

aggressive_multi_coin - 多币种激进策略：
  - 特点: 多币种交易，高杠杆(10x/8x)，短持仓(15分钟)，高频交易
  - 适用: 风险承受能力强的投资者
  - 配置亮点: max_positions=5, trading_style_preset="short", 启用mixed币源

quant_data_focused - 量化数据驱动策略：
  - 特点: 重点利用OI和资金流向数据，结合技术分析
  - 适用: 相信数据驱动决策的投资者
  - 配置亮点: 启用所有quant_data和ranking_data，custom_prompt强调数据重要性

使用建议：
AI可根据用户需求选择合适的模板作为基础，然后进行个性化调整。

--------------------------------------------------------------------------------
2.6 _validation_checklist - 验证检查清单
--------------------------------------------------------------------------------

before_submit - 提交前检查项：
  - name和description已填写且符合长度要求
  - config.language为'zh'或'en'
  - coin_source.source_type为有效枚举值
  - 当source_type='static'时，static_coins不为空
  - indicators.klines.primary_timeframe为有效时间周期
  - risk_control中所有数值在有效范围内
  - 百分比值使用小数形式(如0.9而非90%)

common_mistakes - 常见错误：
  - 使用'90%'而非0.9表示百分比
  - timeframe使用'1H'而非'1h'(必须小写)
  - static_coins包含空格或格式错误
  - 数值类型错误(如使用字符串'5'而非数字5)

2.7 _complete_example - 完整示例
--------------------------------------------------------------------------------

提供一个完整的、可直接使用的策略配置示例。
AI可以参考此示例的：
  - 字段完整性和组织结构
  - 各字段的典型取值
  - 配置之间的逻辑关系

================================================================================
三、使用指南
================================================================================

场景1: 用户要求生成一个保守型BTC策略
  步骤:
  1. 参考 _strategy_templates.conservative_btc_eth
  2. 根据用户具体需求调整参数
  3. 使用 _validation_checklist 验证
  4. 输出完整JSON

场景2: 用户有特定需求（如"只做合约持仓量前10的币种"）
  步骤:
  1. 设置 coin_source.source_type = "oi_top"
  2. 设置 coin_source.use_oi_top = true
  3. 设置 coin_source.oi_top_limit = 10
  4. 参考其他模板调整risk_control参数

场景3: 用户要求自定义AI行为
  步骤:
  1. 使用 custom_prompt 添加特定规则
  2. 或使用 prompt_sections 修改系统提示词段落
  3. 确保修改内容与策略目标一致

================================================================================
四、重要注意事项
================================================================================

1. 数据类型严格性
   - 所有字段必须符合声明的类型
   - 特别注意number和string的区别
   - 数组类型必须使用[]而非其他格式

2. 枚举值准确性
   - timeframe必须使用小写: "1h"而非"1H"
   - source_type必须是: "static"/"ai500"/"oi_top"/"mixed"
   - language必须是: "zh"或"en"

3. 百分比表示
   - 使用小数形式: 0.9表示90%
   - 不是字符串: 0.9而非"0.9"或"90%"

4. 币种代码格式
   - 使用标准格式: "BTCUSDT"
   - 不要加空格: "BTCUSDT"而非"BTC USDT"
   - 检查拼写: "ETHUSDT"而非"ETHUSD"

5. 可选字段处理
   - 可选字段可以省略或使用默认值
   - 但不要将必填字段留空
   - 不确定时参考_complete_example

五、示例对话流程
================================================================================

用户: "帮我创建一个专注BTC和ETH的保守策略"

AI思考过程:
  1. 确定风格: 保守型 → 参考conservative_btc_eth模板
  2. 确定币种: BTC和ETH → source_type="static", static_coins=["BTCUSDT","ETHUSDT"]
  3. 调整杠杆: 保守 → btc_eth_max_leverage=3
  4. 调整仓位: 保守 → max_margin_usage=0.7, max_positions=2
  5. 调整风控: 严格 → max_loss_per_trade_percent=2, daily_loss_limit_percent=1
  6. 验证: 使用_validation_checklist检查
  7. 输出: 生成完整JSON

================================================================================
六、故障排除
================================================================================

问题1: 导入策略时提示"无效的策略文件"
  可能原因:
  - 缺少name或config字段
  - JSON格式错误
  - 字段类型不匹配
  解决方法: 使用_validation_checklist逐项检查

问题2: 策略保存后某些设置不生效
  可能原因:
  - 字段拼写错误
  - 数值超出有效范围
  - 使用了不支持的枚举值
  解决方法: 对照_schema_overview检查字段名和类型

问题3: AI交易行为与预期不符
  可能原因:
  - prompt_sections设置不当
  - custom_prompt与策略目标冲突
  - risk_control参数限制过于严格
  解决方法: 检查prompt相关配置，调整参数范围
