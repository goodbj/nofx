# nofx 独立运行开发指南

## 🚀 独立运行nofx的优势

### 1. **开发效率提升**
- **快速启动**：无需等待Docker容器启动，后端程序秒级启动
- **实时调试**：可使用IDE调试器直接断点调试
- **资源节省**：避免Docker虚拟化开销，CPU和内存占用更低
- **网络稳定**：无需处理Docker网络配置，避免网络不稳定问题

### 2. **开发体验优化**
- **热重载**：后端代码修改后自动重启（使用air等工具）
- **日志清晰**：直接在终端输出，无需进入容器查看日志
- **本地环境**：可使用本地工具链（如curl、postman等）直接测试API

### 3. **部署灵活性**
- **快速切换**：可在开发/测试/生产环境间快速切换
- **资源隔离**：不同项目可使用不同端口，互不影响

## ⚠️ 开发注意事项

### **需要重启后端的情况：**
1. **Go代码修改**：
   - `*.go` 文件修改后需要重启后端
   - 包括 `api/`, `trader/`, `kernel/`, `backtest/` 等目录下的Go文件

2. **配置文件修改**：
   - `config/config.go` 中的配置项修改
   - `.env` 环境变量文件修改

3. **数据库结构变更**：
   - `store/` 目录下涉及数据库表结构的修改
   - GORM模型定义修改

4. **路由定义修改**：
   - `api/server.go` 中的路由定义修改

### **后端自动更新的情况：**
1. **静态资源**：
   - `web/dist/` 下的前端文件修改会自动生效
   - 前端构建后直接覆盖即可

2. **配置文件（部分）**：
   - 某些运行时可重载的配置（如策略配置）
   - 通过API接口动态更新的配置

## 📋 常见文件变更处理清单

| 文件类型 | 位置 | 是否需要重启后端 | 备注 |
|---------|------|----------------|------|
| Go源码 | `*.go` | ✅ 是 | 包括api, trader, kernel等模块 |
| 环境变量 | `.env` | ✅ 是 | 重启后生效 |
| 配置结构 | `config/` | ✅ 是 | 涉及结构体定义修改 |
| 前端代码 | `web/src/` | ❌ 否 | Vite热更新 |
| 静态资源 | `web/dist/` | ❌ 否 | 直接覆盖生效 |
| 数据库模型 | `store/` | ✅ 是 | 影响数据库结构 |

## 🔧 推荐的开发工作流

### **后端开发：**
```bash
# 使用air实现热重载
go install github.com/cosmtrek/air@latest
air -c .air.toml  # 如果项目有.air.toml配置文件
# 或者直接运行
go run main.go
```

### **前端开发：**
```bash
cd web
npm install
npm run dev  # 在 http://localhost:5173 运行
```

### **调试技巧：**
1. **IDE集成调试**：直接在VS Code等IDE中设置断点调试
2. **日志级别**：开发时可调整日志级别获取更多信息
3. **API测试**：使用Postman或curl直接测试API端点

## 💡 效率提升建议

1. **使用热重载工具**：如air或gin，实现代码修改自动重启
2. **分离开发环境**：前后端分别在不同终端运行，便于查看各自日志
3. **API文档**：利用Swagger或其他工具实时查看API变更
4. **Git钩子**：设置pre-commit钩子自动格式化代码

这种独立运行的方式确实大大提升了开发效率，特别是在快速迭代和调试阶段非常有用！
